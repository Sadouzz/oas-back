1. Présentation des Travaux Réalisés

Pour ce sprint de 4 jours, nous avons mis en place une architecture modulaire complète en Java (Spring Boot, JPA) pour la partie mobile client. Voici les composants développés :

  • Inscription & Session Client : Prise en charge de la création de comptes clients avec génération automatique incrémentielle du matricule au format CLT-xxxxx (ex: CLT-00001) s'il n'est pas fourni par le front-end. Ajout d'une méthode pour récupérer le client connecté à partir du token JWT.
  • Module Rendez-vous : Création de la table rendez_vous et gestion complète des rendez-vous (enregistrement, liste et annulation par le client ; validation/refus avec commentaire par les agents).
  • Suivi de Réparations : Ajout d'un système d'avancement des travaux (statuts : A_FAIRE, EN_COURS, TERMINE, LIVRE) pour chaque fiche d'atelier.
  • Factures et Paiements Partiels : Intégration de la gestion des versements partiels ou totaux. Le statut de facturation s'adapte automatiquement (PARTIELLEMENT_PAYEE, PAYEE) et génère des reçus de paiement (Recu).
  • Notifications In-App : Système d'historique de notifications in-app pour alerter les clients des changements importants (validation de rendez-vous, paiements reçus, avancement).
  • Messagerie Client : Chat bidirectionnel REST pour échanger des messages avec l'atelier de réparation, incluant un compteur de messages non lus pour les agents.

2. APIs du Portail Client (/api/client/**)

Toutes les requêtes de cette section doivent inclure le header d'authentification Authorization: Bearer <JWT_TOKEN> d'un utilisateur ayant le rôle ROLE_CLIENT.

Méthode Endpoint Description
GET /api/client/me Récupérer les informations du profil du client connecté
GET /api/client/vehicules Lister tous les véhicules appartenant au client
POST /api/client/vehicules Enregistrer un véhicule pour le client connecté
GET /api/client/rendezvous Lister l'historique des demandes de rendez-vous
POST /api/client/rendezvous Créer une demande de rendez-vous
PUT /api/client/rendezvous/{id}/annuler Annuler un rendez-vous (statut passe à ANNULE)
GET /api/client/interventions Lister l'historique et l'avancement des réparations
GET /api/client/interventions/{id} Détail d'une fiche d'atelier/intervention
GET /api/client/factures Lister l'historique de facturation du client
GET /api/client/factures/{id} Détail d'une facture client
GET /api/client/recus Lister l'historique des reçus de paiement du client
GET /api/client/notifications Lister les notifications in-app
PUT /api/client/notifications/{id}/lu Marquer une notification spécifique comme lue
PUT /api/client/notifications/lu-tout Marquer toutes ses notifications comme lues
GET /api/client/messages Récupérer la discussion avec le support de l'atelier
POST /api/client/messages Envoyer un message au support de l'atelier

Exemple de requête : Enregistrement de véhicule (POST)

{
  "immatriculation": "DK-8849-B",
  "marque": "Toyota",
  "modele": "Hilux",
  "annee": 2022,
  "kilometrage": 34000.0,
  "numeroChassis": "AHR1239840294820"
}

Exemple de requête : Prise de rendez-vous (POST)

{
  "dateRendezVous": "2026-06-15T09:30:00",
  "motif": "Changement de plaquettes de frein",
  "vehiculeId": 3
}

3. APIs du Backoffice / Agents (/api/admin/portal/**)

Ces endpoints permettent aux agents/magasiniers de l'atelier de gérer l'interaction avec le Portail Client.

Méthode Endpoint Description / Paramètres
GET /api/admin/portal/rendezvous Lister tous les rendez-vous clients enregistrés
PUT /api/admin/portal/rendezvous/{id}/statut Valider ou refuser un rendez-vous.
Query Params : statut (CONFIRME, REFUSE, TERMINE), commentaire (optionnel)
POST /api/admin/portal/factures/{id}/payer Enregistrer un paiement pour une facture.
Query Params : montant (optionnel - si vide, paie le solde), methodePaiement (ESPECES, CARTE, WAVE, ORANGE_MONEY)
GET /api/admin/portal/messages/clients Tableau de bord messagerie : liste des clients actifs et messages non lus
GET /api/admin/portal/messages/clients/{clientId} Récupérer la discussion avec un client spécifique (les marque comme lus)
POST /api/admin/portal/messages/clients/{clientId} Envoyer un message de réponse au client.
Body : {"contenu": "Message de réponse"}

4. Accès à Swagger UI

Informations Importantes

Le serveur de l'application tourne sur le port 9090 par défaut.

Les URLs d'accès à la documentation interactive Swagger sont les suivantes :

  • Swagger UI (Page HTML) : http://localhost:9090/swagger-ui/index.html
  • Redirection automatique : http://localhost:9090/swagger-ui.html
  • Spécification OpenAPI (JSON) : http://localhost:9090/v3/api-docs

Pourquoi Swagger ne s'ouvre-t-il pas ?

Si la page Swagger ne s'ouvre pas (Erreur de connexion), vérifiez que :

  1. L'application Spring Boot a démarré avec succès. S'il y a un crash à cause de la base de données PostgreSQL ou de variables d'environnement manquantes dans votre fichier .env, Swagger ne sera pas accessible.
  2. Le port utilisé est bien 9090. Si vous l'avez modifié dans application-dev.yml, adaptez l'URL de Swagger en conséquence.
